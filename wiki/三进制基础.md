# 三进制基础（trit-core）

三值逻辑 **{-1, 0, +1}**（False / Unknown / True）不是"二进制省一位"的花招：
Unknown 是**一等信息**——"不知道"与"假"必须能区分。整个栈的算子都围绕这一点设计。

## 1. 三种强代数

三值逻辑里"与/或"有多个自洽定义，trit 同时实现三种，按场景选：

| 代数 | 强与（and） | 特征 |
|---|---|---|
| **Kleene** | 只要有一边 False 就 False；否则有 Unknown 就 Unknown | 三值逻辑的默认 |
| **Bochvar** | 同上（内部语义不同，真值表一致） | 悖论/自指场景 |
| **Łukasiewicz** | `s = a + b − 1`：`s ≤ 0 → F`，`s ≥ 1 → T`，否则 U | 连续化，可映射到 [0,1] 区间 |

为什么要三种：Kleene 适合"未知传播"，Łukasiewicz 适合"程度可加"（把真值当权重）。
混用会静默错——所以 API 上代数是一个**显式参数**，不是全局开关。

## 2. B3 位编码

`TriBit` 用 **2 bit** 表示一个三值（`00/01/10`），空出的 `11` 是非法态（rail）。
位并行（bit-sliced）运算把 64 个三值塞进两个 u64：`pos` / `neg`。强与/或/非都在位运算里完成，
没有分支——这是"三值不等于慢 1.5 倍"的关键。

工程约束：**二进制/三值边界要接近零开销**。`TriVec`/`TriBit` 的转换、`from_binary` 的截断、
非法 rail 的规范化都有判据（`bulk.rs`）。

## 3. 容量与门

- 一致性检查、真值表对拍、随机向量高压测试（`trit-capacity`）。
- 变异门要求：关键规则（如 Łukasiewicz 强与、rail 规范化）都要有**判决性单测**，
  单点变异必须让测试变红（见[工程门禁](工程门禁与复现)）。

## 4. 和上层的关系

| 层 | 用三进制做什么 |
|---|---|
| `trit-learn` | 权重三值化（{-1,0,+1} × scale），STE 训练 |
| `trit-eval` / `trit-sat` / `trit-bdd` | 三值表达式求值、可满足性、BDD |
| `trit-parts` | 三值卷积网（部件头/深度头），权重三值 |
| `trit-immune` | 安全裁决：unknown 不折叠成 allow/deny |

## 5. 常识纠正

- **三值不是 f32 的近似**：前向是精确的 `round(w/scale).clamp(-1,1)`，推理逐位可复现。
- **Unknown ≠ 0**：数值上可以用 0 存，但语义上 0 是"零"，Unknown 是"未知"；算子必须区分
  （这也是为什么有三种代数、以及双轨编码）。
- **量化误差与容量是两件事**：三值权重缩小的是表示空间，不是精度位数。
